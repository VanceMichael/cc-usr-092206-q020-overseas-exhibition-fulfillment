# 海外展会本地化履约

服务不止于三天撤展：支持海外商品展从参展准备、现场对接到本地渠道与订单落地的全过程履约。

当前参与方：中国参展企业、马来西亚采购商、本地渠道伙伴、展会主办方。示例场景为一家中国宠物用品企业参加吉隆坡商品展（`fixtures/kuala-lumpur-pet-scenario.json`）。

## 平台覆盖的业务环节

**参展前**
- 企业资质提交、主办方审核（驳回必须记录原因），资质通过后才能登记展品、申报样品；
- 产品类别按企业申报范围登记，超类别展品无法上架；
- 样品入境申报与清关审核，暂扣样品记录原因，**未清关样品不得寄给买家测试**；
- 展位分配与活动档期安排，时段冲突自动拦截。

**现场**
- 名片线索按意向分三级：`browsing`（现场浏览）、`sample_testing`（已安排样品测试）、`channel_interest`（本地渠道愿意承接订单）；
- 采购需求、翻译支持、洽谈纪要、报价都关联到**准确主体**；
- 直播合作授权可按内容片段撤回，撤回原因保留，撤回后立即对渠道不可见；
- 报价带有效期，买家只看到仍有效的报价，成交后锁定。

**展后**
- 同一买家多张名片可合并，线索、需求、洽谈、报价、订单、样品寄送全部改挂主档；
- 订单可按批次拆分，拆分明细必须恰好覆盖原单，母单保留拆分原因；
- 合作终止双方互留原因，此后渠道看不到对方材料；
- 联系资料只在双方同意的具体用途下延续（如「样品与订单跟进」），撤回授权立即失效，用途不混用；
- 马来西亚合作方只看到**与自己类别匹配且仍有效**的材料；
- 参展商可循着样品测试与拆分订单持续跟进；
- 成效以可核验的转化漏斗（线索 → 测样 → 有效报价 → 订单 → 履约）呈现，每个数字都附带构成它的记录编号，履约进度精确到数量。

## 代码结构

| 路径 | 说明 |
| --- | --- |
| `src/platform.js` | 平台核心领域逻辑：主体、资质、展品、样品、档期、线索、洽谈、直播、报价、订单、合并/终止/授权、展后视图与报告。全部为纯数据操作，无外部依赖 |
| `src/scenario.js` | 声明式场景回放器：把 JSON 脚本按 `ref` 引用映射为平台操作，产出各角色视图 |
| `fixtures/domain.json` | 领域事实样例 |
| `fixtures/kuala-lumpur-pet-scenario.json` | 吉隆坡宠物用品展端到端示例（名片分级、身份合并、直播撤回、报价失效、订单拆分、合作终止、授权撤回） |
| `contracts/domain.schema.json` | 领域资料契约 |
| `contracts/scenario.schema.json` | 场景脚本契约（含全部操作类型枚举与原因字段约定） |

### 关键约定

- **原因留痕**：临时换展、代表缺席、身份合并、直播撤回、订单拆分、合作终止、授权撤回、资质驳回、样品暂扣，均强制填写原因，并写入 `store.changes` 审计日志。
- **记录编号可核验**：报价、订单、样品寄送等全部带稳定编号；转化报告的每一阶段附记录编号列表，已拆分母单不与子单重复计数。
- **最小权限可见性**：渠道视图过滤资质状态、类别匹配、合作状态与内容撤回状态；联系方式仅在存在有效用途授权时附带。
