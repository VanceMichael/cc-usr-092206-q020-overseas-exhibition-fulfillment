# 海外展会本地化履约

支持海外商品展从参展准备、现场对接到展后订单落地的**展会履约平台**：服务不在三天撤展时结束，而是沿着样品、报价和订单继续运转。

以一家中国宠物用品企业参加吉隆坡商品展（示例届会 `2026-KL-PET`）为样本，同时服务主办方与参展双方。

## 平台覆盖的履约阶段

### 展前：资质、品类、样品入境、展位与活动档期

- `qualifications`：企业资质由**主办方**核验，已核准的产品类别约束可展产品；
- `product_catalog` / `samples`：产品与样品登记；样品区分已清关、海关滞留（如等待 SIRIM 认证的电器）并记录许可号，未清关样品不得上展位、不得进入送测；
- `booths` / `show_activities` / `activity_slots` / `representatives`：展位、产业对接会、直播间档期与到场代表预先编排。

### 现场：一切交互关联到准确主体

- `identities` + `name_cards`：每张名片解析为主体身份；同一买家的多张名片（如门店名与公司名）凭工商注册号**合并**，避免重复计数与重复报价，被合并身份不再被任何记录引用；
- `demands`：区分"现场浏览 / 已报价 / 已安排样品 / 已下单 / 报价过期"等阶段，分清谁只是看看、谁在测样、谁真的愿意承接订单；
- `interpretation_sessions`：翻译支持挂接到具体需求；
- `livestream_authorizations` / `livestreams`：直播按授权范围（产品演示、价格展示、品牌标识等）进行，授权对方只能是本地直播合作方；
- `meeting_minutes` / `quotes`：洽谈纪要把出席主体、己方代表、翻译、有效报价串在一起，报价金额=单价×数量并带有效期。

### 变更：六类例外情形必须留痕（含原因与操作人）

`change_events` 对下列情形各至少有一条记录，且与相关单据双向关联：

| 情形 | 关键约束 |
| --- | --- |
| 临时换展品 `exhibit_swap` | 调换前后样品 + 展位 + **主办方现场批准** |
| 代表缺席 `representative_absent` | 缺席者状态、替代者须实际承接对应档期 |
| 同一买家身份合并 `identity_merge` | 同一机构内、存废双向回指，旧身份停用 |
| 直播内容撤回 `livestream_retraction` | 具体到片段，撤回记录与事件双向关联（如口播价已失效） |
| 订单拆分 `order_split` | 拆分数量、金额合计必须与原单**勾稽相等** |
| 合作终止 `collaboration_terminated` | 终止同时撤回相关直播授权 |

### 隐私：联系资料只按双方同意的用途延续

`contacts` 记录联系方式、同意依据（签署表/名片/线上勾选）、用途与有效期。用途分为报价跟进、样品测试跟进、订单履约三类；任何跟进、下单都必须在对应用途的**有效期内**进行，过期不得继续促销联系。

### 展后：匹配且仍有效的材料才可见

`materials` + `visibility_grants`：马来西亚合作方看到的材料必须同时满足——

1. 接收方是马来西亚本地主体；
2. 材料类别与其登记需求**匹配**；
3. 材料关联的报价**仍有效**（报价过期后可见性自动失效并记录原因）；
4. 海关滞留、无有效报价的产品材料不对外可见。

### 跟进链与可核验成效

- `sample_followups` 把 **样品 → 需求 → 报价 → 订单** 串成可回溯的链：参展商可循着样品和订单持续跟进，下单产品须与送测样品一致；
- `outcomes` 为本届服务成效：转化漏斗（名片→去重买家→需求→送样→有效报价→成交金额）、履约进度（在途/部分履约/拆单批次完成情况）和样品转化，每个数字都附带证据 ID 清单，必须能由底层记录**复算一致**，不接受手工填报。

## 领域资料

`contracts/domain.schema.json` 规定共享资料结构（v2），`fixtures/domain.json` 保存不含真实个人信息的示例。参与方包括中国参展企业、马来西亚采购商、本地渠道伙伴、展会主办方、本地直播合作方与现场翻译服务商。示例中的联系渠道均为占位假数据。

资料所依据的领域事实与整体约束记录在 fixture 的 `facts` 与 `constraints` 中。

## 本地校验

读取模块 `src/domain.js` 在 JSON 结构之外执行跨实体校验：引用完整性、身份合并规则、六类变更的原因与交叉引用、报价/订单/拆单金额勾稽、同意用途与期限覆盖、材料匹配且有效、以及成效数字可复算。

运行：

```bash
npm test
```

仓库不保存账号、密钥、连接串或真实身份信息。
